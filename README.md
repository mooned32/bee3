# Bee3

Криптографическая библиотека — преемник Bee2 (НИИ ППМИ БГУ).

Bee3 не является «версией 3» Bee2: Bee2 и Bee3 не образуют версионной
линейки. Bee3 наследует алгоритмы и проверенные наработки Bee2 и
расходится с ним в требованиях к безопасности, сборке и API.

## Состояние

Каркас, инфраструктура сборки, шифры `belt` и `bash`, программируемые
алгоритмы и генератор псевдослучайных чисел. Остальное не перенесено.

```
include/bee3/            публичные заголовки
  defs.h                 маркировка API, контроль конфигурации сборки
  core/                  очистка памяти, работа с секретами, самопроверка
  crypto/belt.h          блочный шифр belt
  crypto/bash.h          sponge-функция bash и хэширование
  crypto/bash_prg.h      программируемые алгоритмы и AEAD
  crypto/brng.h          генерация псевдослучайных чисел
  crypto/legacy/         устаревшие примитивы (собираются только по запросу)
src/crypto/belt/         belt: табличное и константно-временное исполнения,
                         сжатие и хэширование
src/crypto/bash/         bash-f, bash-hash и bash-prg
src/crypto/brng/         имитовставка, генераторы и одноразовые пароли
                         СТБ 34.101.47-2017
src/crypto/kat/          проверочные данные, общие для тестов и самопроверки
cmake/                   строгие наборы флагов
tools/                   проверки, запускаемые в CI
docs/LEGACY.md           что исключено и почему
docs/notes/              разборы примитивов
```

## Сборка

```sh
cmake --preset rel
cmake --build --preset rel
ctest --preset rel
```

Требуется CMake 3.25+, компилятор с поддержкой C23.

## Правила сборки

| Правило | Механизм |
|---|---|
| Расширения компилятора — ошибка | `-pedantic-errors`, `CMAKE_C_EXTENSIONS OFF`, `/permissive-` |
| Предупреждения — ошибки | `-Wall -Wextra -Werror` плюс ~35 специализированных флагов |
| Устаревшее API не компилируется | `-Werror=deprecated-declarations` |
| Устаревшие примитивы вынесены | `BEE3_ENABLE_LEGACY` (по умолчанию `OFF`), список в `docs/LEGACY.md` |
| Статический анализ | `BEE3_CLANG_TIDY` (по умолчанию `OFF`), конфигурация в `.clang-tidy` |
| Алгоритмы проверяются перед первым использованием | `bee3SelfTest()`, требование СТ.3 СТБ 34.101.27-2022 |
| Очистка секретов реальна | `tools/check_nobuiltin.sh` проверяет машинный код |
| Разделение legacy герметично | `tools/check_legacy_leaks.py` обходит дерево `#include` |
| Все меры защиты активны | стек-протектор, `_FORTIFY_SOURCE`, RELRO, BIND_NOW, NX-стек, скрытая видимость символов |

Статический анализ — по требованию: инструмент дорог и требует установки.

```sh
cmake --preset rel -DBEE3_CLANG_TIDY=ON
cmake --build --preset rel
```

Проверки конфигурации:

```sh
python3 tools/check_legacy_leaks.py
bash    tools/check_nobuiltin.sh
```

Те же проверки выполняются в `.github/workflows/build.yml`: сборка и тесты
в четырёх конфигурациях, проверки конфигурации, соответствие `clang-format`.
Анализ `clang-tidy` запускается отдельно — при ручном запуске или при
коммите с `[tidy]` в сообщении.

## Что реализовано

| Примитив | Стандарт | Проверка |
|---|---|---|
| `belt` — блочный шифр, 128/192/256 бит ключа | СТБ 34.101.31-2020 | вектор приложения А.1, побайтово с эталоном |
| `bash-f` — sponge-функция, состояние 1536 бит | СТБ 34.101.77-2020 | таблицы А.1 и А.2 |
| `bash-hash` — хэширование, 256/384/512 бит | СТБ 34.101.77-2020 | таблица А.3 (11 значений) + 579 пар с эталоном Bee2 |
| `bash-prg-hash` — расширяемое хэширование | СТБ 34.101.77-2020 | таблица А.5 + 240 операций с эталоном Bee2 |
| `bash-prg-ae` — аутентифицированное шифрование | СТБ 34.101.77-2020 | 240 операций с эталоном + проверки подмены и очистки |
| `belt-compress` — сжатие | СТБ 34.101.31-2020 | таблица А.8 (S и Y) + 20 000 входов с эталоном |
| `hmac-hbelt` — имитовставка в режиме HMAC | СТБ 34.101.47-2017 | таблица В.1 + 20 000 случаев с эталоном |
| `brng-ctr-hbelt` — генерация в режиме счётчика | СТБ 34.101.47-2017 | таблица В.2 + 4 000 случаев с эталоном |
| генерация в режиме HMAC | СТБ 34.101.47-2017 | таблица В.4 + 4 000 случаев с эталоном |
| `otp-dt`, HOTP, TOTP — одноразовые пароли | СТБ 34.101.47-2017, прил. А | таблицы В.5 и В.6 |
| `bee3SelfTest` — самопроверка всех алгоритмов | СТБ 34.101.27-2022, СТ.3 | вызывается прикладной системой |

`belt-hash` используется только как функция `h` внутри HMAC и генераторов
СТБ 34.101.47-2017 — там от неё требуется псевдослучайность, а не стойкость
к коллизиям. Как самостоятельный хеш она не предлагается; позиция разобрана
в `docs/LEGACY.md`, п. 3.2.

Константно-временность: `bash-f` константно-временна по построению — в `bash-s`
нет ни одного обращения к памяти по индексу, зависящему от данных. У `belt`
две версии: табличная (быстрая, не константно-временная) и битовый срез по
32 блокам, константно-временный по построению. Выбор версии — вопрос модели
угроз, а не вопрос вкуса; см. `docs/notes/001-belt-h.md` и
`docs/notes/005-belt-slice.md`. Константно-временность среза доказана
структурно, а не измерением. Сравнение имитовставки при снятии защиты
выполняется константно-временно (`bee3SecureEq`), иначе величина 128 бит
теряла бы смысл: подбор байт по одному со сложностью порядка 2^64.

## Документация

Документы проекта оформлены по ГОСТ 7.32-2017: реферат, перечень сокращений,
введение, основная часть, заключение, список использованных источников.
Библиографические записи составлены по ГОСТ Р 7.0.5-2008 и
ГОСТ Р 7.0.100-2018.

- `docs/LEGACY.md` — материал, исключённый из сборки по умолчанию,
  с основаниями и заменами;
- `docs/notes/001-belt-h.md` — подстановка H шифра belt и вопрос
  константно-временности;
- `docs/notes/002-bash.md` — sponge-функция bash, константно-временность по
  построению и расхождение в описании дополнения сообщения;
- `docs/notes/003-bash-prg.md` — программируемые алгоритмы и аутентифицированное
  шифрование с имитовставкой 128 бит и более;
- `docs/notes/004-belt-compress.md` — сжатие и хэширование belt, семь ошибок
  переноса одного класса и переполнение буфера в HMAC;
- `docs/notes/005-belt-slice.md` — локализация расхождения константно-временного
  среза belt: пропущенная перестановка после последнего такта;
- `docs/notes/006-ctb-27.md` — соответствие требованиям СТБ 34.101.27-2022
  и разграничение ответственности между библиотекой и прикладной системой;
- `docs/notes/007-bign-blocked.md` — почему подпись на эллиптических кривых
  не перенесена: проверочные примеры стандарта не воспроизводятся.

## Ограничения

- C как основной язык. C++23 рассматривается только для типизированного
  слоя поверх.
- Алгоритмы на эллиптических кривых (`bign`) не перенесены: проверочные
  примеры СТБ 34.101.45-2013 не воспроизводятся, эталон отсутствует,
  а подпись без проверяемого примера опаснее отсутствующей. См.
  `docs/notes/007-bign-blocked.md`.
- Остальные примитивы и форматы не перенесены, библиотека непригодна для
  применения. Это сделано намеренно: публиковать криптографию под именем Bee3
  до переноса и проверки механизмов защиты было бы хуже, чем не публиковать
  её вовсе.
- `belt-hash` не предлагается как хеш стойкости к коллизиям: он построен по
  схеме Меркла — Дамгорда. Используется только как `h` внутри HMAC и
  генераторов, см. `docs/LEGACY.md`, п. 3.2.
- Константно-временность среза `belt` доказана по построению, а не
  измерением: измерение побочного канала на собственной машине
  доказательством не является.
- Найдено одно расхождение в тексте СТБ 34.101.77-2020 (описание дополнения
  сообщения), см. `docs/notes/002-bash.md`, п. 2.5.
- Bee3 **не является средством криптографической защиты**: это библиотека,
  то есть собственный компонент СКЗИ по терминологии СТБ 34.101.27-2022.
  Требования к источнику энтропии, управлению ключами, ролям и блокировке
  адресованы прикладной системе, см. `docs/notes/006-ctb-27.md`.
- Генератор псевдослучайных чисел не является источником энтропии: он
  разворачивает ключ в последовательность. Ключ должен вырабатываться
  генератором случайных чисел прикладной системы, см. `docs/notes/006-ctb-27.md`
  и п. 5.3 СТБ 34.101.47-2017.
- Синхропосылка обязана быть уникальной для данного ключа. Повтор приводит
  не к защите от повтора, а к его отсутствию.
