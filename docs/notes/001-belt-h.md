# 001. Подстановка H в шифре belt и константно-временность

**Статус.** Расследование завершено частично. Измерения ниже — результат,
а не оценка. Выводы, меняющие решения, помечены как требующие новой
редакции стандарта.

---

## 1. Что предписывает стандарт

СТБ 34.101.31-2020, п. 6.1.2:

> Подстановка H. Подстановка H : {0,1}^8 → {0,1}^8 задается таблицей 2.
> В таблице входы (прообразы) и выходы (образы) H записываются в
> шестнадцатеричном виде.

То есть **256 значений, и ничего кроме них**. Безтабличной, регулярной
или арифметической формы стандарт не содержит.

Сравнение: ГОСТ Р 34.12-2015 для своей подстановки приводит и табличную,
и регулярную форму — там прямо сказано, что реализация обязана быть
устойчивой к атакам по времени выполнения.

Проверялось также наличие формулировок о безтабличном исполнении: в тексте
СТБ 34.101.31 их нет.

---

## 2. Измеренная алгебраическая степень

Подстановка H, восстановленная из таблицы 2 и извлечённая из реализации
Bee2, разложена по анфирной форме отдельно для каждого выходного бита.

| Выходной бит | Степень | Мономиалов |
|---|---|---|
| 0 | 7 | 125 |
| 1 | 7 | 130 |
| 2 | 7 | 137 |
| 3 | 7 | 133 |
| 4 | 7 | 137 |
| 5 | 7 | 132 |
| 6 | 7 | 122 |
| 7 | 7 | 122 |

**Степень H равна 7 при максимально возможной для подстановки 8×8,
равной 8.** Это не приблизительная оценка, а точный результат разложения.

Следствие, определяющее всю дальнейшую работу: подстановка степени 7
**не раскладывается** через 4-битные таблицы. Композиция двух независимых
4-битных перестановок даёт степень не выше 4; Фейстель из двух 4-битных
перестановок — не выше 6. Поэтому:

> Дешёвой безтабличной константно-временной подстановки для H
> не существует. Это свойство спецификации, а не дефект реализации.

Проверено также, что H не совпадает с подстановкой ГОСТ Р 34.12-2015 и не
является её композицией с перестановкой октетов или разворотом битов:
совпадений — ноль из 256.

## 3. Что удалось реализовать и проверить

Все проверки выполнены против табличной эталонной реализации, проверенной
по вектору приложения А.1.

| Компонент | Проверка | Результат |
|---|---|---|
| `bee3BeltKeyExpand` | три длины ключа | совпадает |
| `bee3BeltBlockEncr/Decr` | вектор А.1, побайтово с Bee2 | совпадает |
| `bee3BeltHslice` | все 256 входов, все 32 дорожки | 0 расхождений |
| `bee3BeltSlicePack/Unpack` | 32 блока | взаимно обратны |
| `slAddInto` / `slSubInto` | 50000 случайных пар, все дорожки | 0 расхождений |
| `gslice`, r = 5, 13, 21 | 20000 входов, все дорожки | 0 расхождений |
| `slRound` | один такт против эталона | совпадает |
| **полная сборка тактов** | | **не сходится** |

Получено подтверждённое свойство:

> G₁₃(x) = RotHi₈(G₅(x)), G₂₁(x) = RotHi₈(G₁₃(x))

Проверено на 3000 случайных значениях для каждого r. Практическое
следствие: все три подстановки сводятся к одной, а поворот дорожек —
перенумерация, то есть операция бесплатная.

## 4. Где локализовано расхождение

Расхождение возникает при сборке тактов. Отдельно проверенные компоненты
дают верный результат по отдельности и верны при одном такте.

**Расхождение не локализовано.** Известно следующее:

- при одном такте (любом i, в любой позиции перестановки) срез совпадает
  с эталоном;
- расхождение появляется начиная со второго такта;
- попытка сравнить полный шифр с эталоном даёт расхождение уже на
  первом такте — то есть результат зависит от способа сборки теста, что
  указывает на состояние, не учитываемое при отладке.

Отсутствие локализации при такой объёме проверок означает, что гипотеза
«ошибка в компоненте» не подтверждается, а гипотеза «ошибка в сборке
тактов или в состоянии» — не исключается. Дальнейшая работа требует
инструментального подхода (проверка каждого такта на границе функции
с эталоном в одном и том же процессе), а не ручной отладки.

## 5. Ошибки, найденные по пути

Все — в коде Bee3, не в спецификации. Перечислены, потому что каждая даёт
результат, который выглядит корректным.

1. **Сложение 32-битных слов сведено к исключающему И.**
   Исключающее И даёт сложение по модулю 2, а такт работает по модулю
   2³², где переносы существенны. Заменено разрядными сумматорами.

2. **Прибавление тактового ключа выполнено как XOR.**
   Та же ошибка в другой форме.

3. **Номер такта передавался в макрос как `++i`.**
   Инкремент выполнялся при каждом из девяти упоминаний, и номер такта
   «уезжал» внутри одного такта.

4. **Плоскость дорожки заполнялась значением вместо битовой развёртки.**
   Присваивание `sk[k][i] = key[k]` выглядит безобидно и даёт верный
   результат на одной дорожке. Ошибка проявляется исключительно при
   сравнении с эталоном.

5. **Константа такта XOR-илась в каждую плоскость целиком.**
   Верно только для младшего бита константы. Та же ошибка, что в п. 4.

6. **Вклад в выход накапливался по битам входного октета вместо выходного.**

Пункты 4 и 5 — один класс ошибки: различие между плоскостью и числом.
Оно формулируется здесь явно, потому что повторилось дважды.

## 6. Решения, которые из этого следуют

### 6.1 Скорректировать формулировку задачи

Изначально предполагалось, что отсутствие константно-временной версии —
дефект реализации, устранимый доработкой. Измерения показывают обратное:
устранению это не подлежит без изменения стандарта.

**Вариант A — новая редакция СТБ 34.101.31.** Определить подстановку с
явной безтабличной формой. Ориентир — ГОСТ Р 34.12-2015. При выборе
следует учитывать измеренный факт: подстановка степени 7 исключает
4-битные разложения, поэтому опорой может быть только явно заданная
арифметическая форма либо составная конструкция.

**Вариант B — признать табличное исполнение допустимым.** Это осознанный
компромисс, а не решение. Тогда он должен быть записан в модель угроз
вместе с указанием, в каких конфигурациях (одно ядро, отсутствие
разделяемых кэшей) предполагается применение, а в каких — запрещено.

**Вариант C — отказаться от belt как от примитива для долговременных
ключей**, оставив его там, где атака по кэшу неприменима.

Вариант B без явной записи в документации недопустим: неявное допущение
недопустимого — это и есть тот дефект, который устраняется.

### 6.2 Что делается сейчас

- Эталонная табличная реализация — в сборке, проверена по стандарту.
- Срез — в дереве, но **не в сборке**. В `CMakeLists.txt` стоит явная
  ошибка конфигурации при попытке его включить.
- Падающие тесты оставлены падать: расхождение должно быть видно, а не
  скрыто отключением теста.

### 6.3 Условие для продолжения

Работу имеет смысл возобновлять после выбора между A и B. Вариант A
требует новой редакции стандарта и вне библиотеки не решается. Вариант B
требует только локализации расхождения, которая пока не достигнута.

---

## 7. Методическая заметка

Работа велась с обязательной проверкой каждого утверждения измерением.
Из шести найденных ошибок **четыре** были обнаружены не размышлением, а
сверкой с эталоном; две из них (пп. 4 и 5) прошли все «очевидные»
проверки и выявлялись только сравнением с эталоном на данных.

Из этого следует правило для проекта: утверждение «функция корректна»
должно сопровождаться тестом, а не рассуждением. Функция, для которой
теста нет, считается непроверенной независимо от того, насколько простым
выглядит код.
