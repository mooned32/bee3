# 005 — Локализация расхождения константно-временного среза belt

## Аннотация

Срез был исключён из сборки, потому что не совпадал с табличной версией
блочного шифра, и расхождение не локализовалось [1]. В настоящей заметке
расхождение локализовано и устранено. Срез проверен и включён в сборку.

Причина оказалась не в тактах и не в арифметике, а в том, что перестановка
указателей не выполнялась после последнего такта. Все восемь тактов
совпадали с эталоном побайтово; расхождался только выход.

Ключевые слова: Кузнечик, битовый срез, константно-временность,
локализация, перестановка указателей.

## Введение

`belt` определён стандартом таблицей, и константно-временного исполнения в
тексте нет. Чтобы получить такое исполнение без новой редакции стандарта,
в проекте сделан битовый срез по 32 блокам: подстановка H вычисляется
раскрытием в сумму по всем 256 значениям, арифметика выполняется над
дорожками.

Первые компоненты были проверены по отдельности и оказались верны. Сборка
тактов с эталоном не сходилась, и расхождение объявлено нелокализованным;
реализация выведена из состава сборки.

Настоящая работа описывает локализацию. Метод тот же, что и в [2]:
реализация сравнивается с эталоном не по итоговому значению, а по
состоянию после каждого такта.

## 1 Основная часть

### 1.1 Что было известно

| Компонент | Проверка | Результат |
|---|---|---|
| `bee3BeltHslice` | все 256 входов | верен |
| `bee3BeltSlicePack` / `Unpack` | взаимная обратимость | верны |
| Арифметика над дорожками | 50 000 пар | верна |
| `gslice` для r = 5, 13, 21 | 20 000 входов | верен |
| `slRound` | один такт | верен |
| **Сборка тактов** | | **не сходилась** |

Утверждение «при одном такте в любой позиции перестановки срез совпадает с
эталоном» при повторной проверке **не подтвердилось**: расхождение
возникало уже на первом такте. Прежняя формулировка была сделана по
результату одной частной проверки и оказалась неверной.

### 1.2 Локализация

Сравнение по тактам с эталонной последовательностью вызовов дало:

| Такт | Вход среза | Вход эталона | |
|---|---|---|---|
| 1 | `11111111 89ABCDEF 00000001 FFFFFFFF` | то же | вход совпадает |
| 2 | `34A24E77 67C25DFE D121E6AC 0E716393` | то же | вход совпадает |
| … | | | |
| 8 | `B128776E C881884F 2FB75F5B EF2ABFF4` | то же | вход совпадает |

Такты 1–8 совпадают с эталоном побайтово. Расхождение возникает только
на выходе.

### 1.3 Причина

Перестановка указателей после такта при зашифровании имеет вид

```
(a, b, c, d) -> (b, d, a, c)
```

и обладает **периодом 4**:

| Такт | Порядок дорожек |
|---|---|
| 1 | P⁰ |
| 2 | P¹ |
| 3 | P² |
| 4 | P³ |
| 5 | P⁰ |
| … | … |
| 8 | P³ |

Эталон объявляет восемь тактов подряд, и перестановка выполняется после
каждого, то есть семь раз. Семь — это 3 по модулю 4. Значит после
последнего такта дорожки находятся в порядке P³, а не P⁰, и завершающая
перестановка применяется к переставленному состоянию.

Исправление: перестановка выполняется **после каждого такта, включая
последний** — восемь раз, 8 ≡ 0 по модулю 4.

Та же ошибка была и в расшифровании: там перестановка не выполнялась
после такта `i = 1`.

### 1.4 Дефект в самом тесте

Проверка расхождения была ошибочной. Тест вызывал
`bee3BeltSliceUnpack(blocks, planes)`, **перезаписывая** массив, из
которого на следующей итерации брался следующий блок. Со второго шага
сравнивался шифротекст с шифротекстом.

Отсюда важное следствие: расхождение, о котором сообщал тест, было
частично следствием ошибки теста, а не только ошибки реализации. Тест,
который локализует дефект, может быть дефектным сам — и это обнаруживается
только сверкой состояний пошагово, а не повторением того же теста.

Третья ошибка теста: проверка «зашифрование среза обратимо на 32 блоках»
сравнивала шифротекст с открытым текстом и ожидала равенства. Заявленный
смысл — инъективность; реализованный — тождественность.

### 1.5 Проверка после исправления

| Проверка | Объём |
|---|---|
| Срез зашифрования против табличной версии | 32 блока |
| Срез расшифрования против табличной версии | 32 блока |
| Случайная сверка на 64 ключах | 64 × 32 блока, обе стороны |
| Расшифрование возвращает исходные блоки | 32 блока |
| Инъективность: блоки попарно различны | 32 блока |
| AddressSanitizer и UndefinedBehaviorSanitizer | без замечаний |

Эталоном служит `bee3BeltBlockEncr`, проверенная по вектору приложения
А.1. Отдельного эталонного среза ни в тексте стандарта, ни в эталонной
реализации нет: битовый срез — изобретение реализации, а не алгоритм
стандарта.

### 1.6 Оговорка о константно-временности

Исправление устраняет расхождение с эталоном, но **не создаёт
доказательства константно-временности**. Доказательство остаётся
структурным: в срезе нет обращения к памяти по индексу, зависящему от
данных, а все циклы имеют фиксированную длину.

Проверка на утечку по времени не проводилась: измерение побочного канала на
собственной машине доказательством не является и создаёт ложную
уверенность. Основания и ограничения изложены в [1].

## 2 Заключение

**Вывод первый.** Расхождение локализовано и устранено. Причина —
пропущенная перестановка указателей после последнего такта, то есть
ошибка на единицу в числе перестановок при периоде 4.

**Вывод второй.** Ошибка была неочевидна, потому что все такты совпадали
с эталоном. Проверка «сходится ли такт» и проверка «сходится ли сборка
тактов» — разные утверждения, и первая не покрывает вторую.

**Вывод третий.** Два из трёх дефектов находились в самом тесте. Тест,
локализующий дефект, сам может быть дефектным; поэтому сверка ведётся по
состояниям, а не повторением того же теста.

**Вывод четвёртый.** Срез включён в сборку. Модель угроз записывается
явно, а не подразумевается: табличное исполнение остаётся основным, срез
применяется там, где противник может измерять время выполнения.
