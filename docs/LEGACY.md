# Материал, исключённый из сборки по умолчанию

## Реферат

Документ фиксирует, какой криптографический материал не входит в обычную
сборку Bee3, по каким основаниям и чем заменяется. Список не является
формальностью: каждой позиции соответствует конкретный модуль сборки,
который физически отсутствует при `BEE3_ENABLE_LEGACY=OFF`, и конкретная
строка в `include/bee3/crypto/legacy/legacy.h`.

Основание включения или исключения — свойства стойкости, а не дата. По
этим свойствам материал разделён на три уровня: помеченный устаревшим по
безопасности, вынесенный в необязательный модуль и не исключённый вовсе.

## Перечень сокращений

- AEAD — аутентифицированное шифрование;
- ГОСТ — межгосударственный стандарт;
- СТБ — стандарт Республики Беларусь;
- PRF — псевдослучайная функция;
- NAF — невзвешенное двоичное представление.

## 1 Введение

Настоящий документ отвечает на вопрос «что и почему отсутствует в
сборке Bee3 по умолчанию». Отсутствие — сознательное решение, и оно
должно быть проверяемым: каждый пункт списка опирается на первоисточник,
а не на мнение об авторе.

Список признан частью проектной документации и не имеет права молча
разъезжаться с содержимым модулей. При изменении состава модулей
правится здесь же.

## 2 Общие положения

### 2.1 Уровни исключения

| Конфигурация | Что происходит |
|---|---|
| `BEE3_STRICT=ON`, `BEE3_ENABLE_LEGACY=OFF` (по умолчанию) | Устаревшие примитивы **не собраны**. Попытка включить `bee3/crypto/legacy/legacy.h` — ошибка компиляции. |
| `BEE3_STRICT=OFF`, `BEE3_ENABLE_LEGACY=OFF` | Устаревшие примитивы не собраны, но функции, помеченные `BEE3_DEPRECATED_SECURITY`, доступны с предупреждением. Режим для поэтапного переноса кода. |
| `BEE3_STRICT=OFF`, `BEE3_ENABLE_LEGACY=ON` | Устаревшие примитивы собраны. Только для переноса с Bee2 и сравнительных испытаний. |

`BEE3_STRICT=ON` вместе с `BEE3_ENABLE_LEGACY=ON` — ошибка конфигурации,
а не конфликт требований: строгая сборка существует ровно затем, чтобы
исключить небезопасные возможности.

### 2.2 Различие двух видов устаревания

«Устарело по времени» — работает правильно, но есть лучшая замена.
«Устарело по безопасности» — даёт результат, который нельзя считать
безопасным при заданных параметрах вызова. Второе не должно
использоваться ни при каких обстоятельствах, даже в сборке с разрешённым
устаревшим материалом; поэтому такие функции всегда доступны и всегда
диагностируются.

## 3 Основная часть

### 3.1 Усечение имитовставок

**Что исключено.** `beltMACStepG2`, `beltMACStepV2`, `beltHMACStepG2`,
`beltHMACStepV2`, усекающие варианты `bash*StepG2/V2`, а также AEAD на их
основе.

**Основание.** СТБ 34.101.31-2020, п. 5.4 устанавливает:

> В алгоритме выработки имитовставки и в алгоритмах аутентифицированного
> шифрования данных вычисляется либо проверяется имитовставка
> T ∈ {0,1}^64. Если требуются не все, а n < 64 символов имитовставки,
> то должны использоваться первые n символов.

Стандарт **фиксирует максимум 64 бита** и **явно разрешает** усечение до
любой длины, включая один бит. Для сравнения, ГОСТ Р 34.13-2015, п. 5.6:

> Параметром режима является длина имитовставки (в битах) 0 < s ≤ n.

Цитата сверена с официальным текстом стандарта (ГОСТ Р 34.13-2015, с. 21).

При размере блока «Кузнечика» n = 128, то есть верхняя граница вдвое
выше. Политика усечения у двух стандартов одинакова, различается
потолок.

**Следствие.** При 64-битном теге достаточно 2^32 попыток для вероятности
подделки 1/2. Общепринятая практика — 128 бит [7; 8].

**Замена.** AEAD с тегом не менее 128 бит. В Bee3 усечение не является
частью API: функции, помеченные `BEE3_DEPRECATED_SECURITY`, ломают сборку
при `BEE3_STRICT=ON`.

### 3.2 belt-hash

**Что исключено.** Хеш конструкции Меркель-Дамгард с 256-битным
внутренним состоянием (СТБ 34.101.31-2020, прил. Д.1).

**Основание.**

- Стойкость к коллизиям ограничена 128 битами независимо от длины
  выхода. Удвоение выхода до 512 бит даёт 256 бит, но не больше.
  Для сравнения: SHA-256 — 128 бит, SHA-512 — 256 бит, SHA3-256 —
  256 бит при том же выходе за счёт 1024-битной ёмкости sponge-конструкции
  [9].
- Конструкция Меркель-Дамгард не обеспечивает мультистойкости и
  устойчивости, свойственных sponge-конструкции.
- Та же линия развития, что у ГОСТ Р 34.11-94 [6], исключённого из
  применения в Российской Федерации.

**Замена.** `bash256` / `bash384` / `bash512` (СТБ 34.101.77-2020). Реализовано
в Bee3, проверено по таблице А.3 и по эталонной реализации Bee2 на 579 парах
«уровень стойкости × длина сообщения»; см. `docs/notes/002-bash.md`.

**Оговорка.** belt-hash остаётся в СТБ 34.101.78-2019 как хеш для уровня
стойкости l = 128 и как хеш PSK по умолчанию в СТБ 34.101.90-2025 [4].
Bee3 реализует его для совместимости, но **не предлагает как примитив по
выбору** и не использует его внутри нового кода.

### 3.3 ГОСТ Р 34.10-94

**Что исключено.** Подпись на кривых с параметрами `1.2.643.2.2.35.0`,
`1.2.643.2.2.35.1/2/3` (наборы A, B, C), `1.2.643.2.9.1.8.1`.

**Основание.** ГОСТ Р 34.10-94 вытеснен ГОСТ Р 34.10-2012 [5]. Эти
параметры присутствуют в Bee2 исключительно ради тестовых векторов и
совместимости с историческими сертификатами. Как самостоятельный примитив
выбора они не нужны.

**Замена.** ГОСТ Р 34.10-2012 (наборы `paramSetA`/`paramSetC`), `bign`,
а в перспективе — ML-DSA (FIPS 204).

### 3.4 ДСТУ 4145-2002

**Что исключено.** Подпись на кривых ДСТУ 4145-2002.

**Основание.** Стандарт не является действующим украинским. Реализация в
Bee2 объёмом около 1200 строк поддерживается только ради исторических
документов.

**Замена.** Ed25519 (RFC 8032) [10], ML-DSA.

### 3.5 belt-pbkdf2

**Что исключено.** Упрощённая редакция PBKDF2 из СТБ 34.101.45-2013,
прил. E.

**Основание.**

- Выход фиксированной длины 32 октета; полноценный PBKDF2 допускает
  произвольный `dkLen`.
- Рекомендация стандарта — `iter >= 10000`. На современной
  GPU/ASIC-аппаратуре это незначительный барьер.
- Функция не обладает стойкостью к подбору, обусловленной памятью
  (memory-hardness), то есть плохо защищена и на специализированной
  микросхеме, оптимизированной под конкретную хеш-функцию.

**Замена.** Argon2id или scrypt для паролей. PBKDF2-HMAC-SHA256 — если
жёсткое требование регулятора важнее стойкости.

### 3.6 belt-sde

**Что исключено.** Секторное шифрование в режиме SDE, построенном на WBL
с изменяющимся раундом.

**Основание.** Режим по замыслу требует одноразового ключа на сектор.
Повторное применение ключа разрушает стойкость полностью и без остатка,
а **ошибка не наблюдаема**: результат выглядит корректным. Класс ошибок,
который невозможно обнаружить в эксплуатации.

**Замена.** AEAD — `belt-dwp`/`belt-che` с тегом 128 бит либо
`bash-prg-ae`.

### 3.7 belt-wbl

**Что исключено.** Шифрование широкого блока как самостоятельный примитив.

**Основание.** WBL не является блочным шифром в смысле PRF и не имеет
документированных гарантий стойкости для самостоятельного использования.
Он существует как внутренний механизм KWP и как основа алгоритма 6.3.3
выработки одноразового ключа подписи.

Дополнительно: на `beltWBL` построен алгоритм 6.3.3 детерминированной
подписи — самодельная конструкция, не соответствующая RFC 6979 [11] и не
имеющая опубликованного обоснования.

**Замена.** HKDF (RFC 5869) [12] для KDF; hedged RFC 6979 для одноразового
ключа; AEAD для сообщений.

### 3.8 Переменные по времени операции с эллиптическими кривыми

**Что исключено.** `ecMulA`, `ecAddMulA`, `ecMulPreNAF` — скалярное
умножение на произвольную точку методом NAF.

**Основание.** Индексация таблицы предвычислений значением цифры NAF
скаляра плюс ветвление по длине представления — канал утечки для любого
случая, где скаляр секретен. Сейчас такие функции применяются только на
публичных данных (проверка подписи), и это правильно: в Bee2 **секретный**
скаляр считается комбинаторным методом с масочным отбором таблицы без
раннего выхода (`wwSel`), что константно-временно.

Проблема в другом: наличие таких функций в публичном API — приглашение к
ошибке. Ошибка будет выглядеть безобидно (проверка подписи), пока не
станет каналом извлечения ключа.

**Замена.** Комбинаторные методы с масочным отбором таблицы — уже
реализованы и применяются на базовой точке. Переменные по времени функции
не выходят из внутреннего слоя.

## 4 Что не исключено и почему

| Материал | Решение |
|---|---|
| SHA-256 | Оставлен. Не уязвим, входит в СТБ 34.101.78-2019 как основной хеш вне AKI/SKI [3]. |
| SHA-1 | Оставлен с оговоркой: СТБ 34.101.78-2019, п. 8.1.2 допускает его только в расширениях SubjectKeyIdentifier и AuthorityKeyIdentifier, с явным обоснованием в тексте стандарта. Bee3 реализует его **только** для этой роли и не для подписей и не для KDF. |
| 192-битные ключи блочного шифра | Оставлены. Присутствуют в СТБ 34.101.31-2020 и в NIST (AES-192). |
| Алгоритмы с уровнем стойкости 192 бит (`bign-curve384v1`, `bash384`) | Оставлены. Соответствуют NIST P-384 по уровню стойкости. |
| Магма (ГОСТ Р 34.12-2015, 64-битный блок) | Не поддерживается вовсе. 64-битный блок вынуждает ограничивать объём данных величиной порядка границы коллизий; в Российской Федерации алгоритм исключён из применения с 1 июня 2024 г. Если нужна совместимость — берётся «Кузнечик» через внешнюю библиотеку. |

## 5 Заключение

Исключение восьми позиций выполнено по единому признаку — невозможность
обеспечить заявленную стойкость при параметрах, принимаемых API. Ни одна
позиция не исключена по дате выхода документа.

Наиболее существенная — п. 3.1: 64-битная имитовставка закреплена
нормативно и попала в профиль TLS 1.3 [1]. Там она присутствует как
допустимая, но не как обязательная: обязательным объявлен
`TLS_BASH_PRG_AE2561_BASH256` с 32-байтовой имитовставкой. Это смягчает
практический риск, но не устраняет нормативную проблему.

## Приложение А

### А.1 Процедура внесения изменений

Приём нового примитива в `BEE3_ENABLE_LEGACY` требует:

1. Записи в `include/bee3/crypto/legacy/legacy.h` с указанием основания.
2. Записи в настоящий документ.
3. Решения о том, чем примитив заменяется.
4. Проверки, что примитив не используется внутри неlegacy-модулей:
   иначе «исключение» перестаёт быть исключением.

Пункт 4 проверяется автоматически: `tools/check_legacy_leaks.py`
разбирает дерево включений и падает, если модуль из
`include/bee3/crypto/legacy/` достижим из обычного public-заголовка.
